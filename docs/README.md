# Affinity MCP 维护文档

这一页面向仓库维护者，说明系统怎么工作、SDK 能力在哪些构建上有证据，以及升级应用后怎样复验。

`docs/` 里的公共技术文档和根目录 `AGENTS.md` 随仓库一起维护。本地专用说明、忽略规则和隐私边界见[文档维护](maintaining.md)；插件的交付范围另按清单和打包方式核对。

开发直接在 `develop` 维护。现行交付步骤见[版本规则](versioning.md#现行交付方式)，正式发布仍需授权。

## 阅读这些记录时

- 插件版本、MCP 协议日期和 Affinity 应用构建号是三个不同的维度。当前仓库清单为插件 `0.5.4`；版本格式和实际交付状态要分开核对。已记录的样本包括 2026-10-08 的 `3.3.0.4850 Win32`，以及 2026-10-19～2026-10-22 的 `3.3.1.4940 MacOS`。后者覆盖了注明的批量、查询、撤销、矩形与海报预览、单行文字光学对齐、双框文本流、异步关闭和已有路径画笔用例。这些样本不等于“官方最新版”。具体来源见[版本身份表](sdk/README.md#version-identity)。
- SDK 能力以具体操作、对象和后置状态为单位记录。函数存在、调用没有异常、文本正确、视觉正确、文件保存成功，各自都需要证据。
- 操作配方默认跨系统共用，实测平台只说明证据来自哪个环境；系统差异要有依据，见[表述约束](maintaining.md#capability-platform-wording)。
- [光学对齐样本](sdk/3.3.1.4940-macos.md#optical-alignment)区分三种情况：可以通过 SDK 设置的模式、查过但没找到的自定义规则入口，以及界面编辑后的实际效果。对象边界对齐不等于中文主体对齐。
- [文本流与异步关闭样本](sdk/3.3.1.4940-macos.md#linked-text-flow-and-close)说明：取消链接后全文留在源框，目标框变空；异步关闭直接丢弃未保存内容。不要把取消链接当作撤销链接，也不要指望保存提示会保护用户的工作。
- [SDK入口与行为补测](sdk/3.3.1.4940-macos.md#sdk-availability)区分 4,260 个函数入口和实际成功样本：普通字符插入、四种布尔、值/像素、五种同步导出、异步 PNG 及保存后重开，只在注明范围内通过；异步复制、两个尺寸反例、默认笔刷和未验证项仍然保留。异步 PNG 成功不能推导出其他异步 API 也成功。
- [已有路径画笔补测](sdk/3.3.1.4940-macos.md#existing-path-brush)验证的是：先在界面准备好真实源笔触，再用 SDK 读取、独立克隆、改宽、复用和恢复历史。单字段掩码生效；不能因此把默认工厂、RasterBrush 或预设枚举一并标成可用。
- [导出、保存与复杂文本扩展](sdk/3.3.1.4940-macos.md#layout-export-save)记录了两页与选页导出、透明混排导出、异步保存覆盖后重开、三框跨 spread 排文和已知高度重排；同时也保留了链首断链清空、混排替换丢格式、默认出血范围不足和资源包离线失真的反例。界面转换不算 SDK 转换，包能打开也不等于原图可用。
- 版本页里的“样本通过”指该页注明日期的既有实验；[脱敏证据摘要](sdk/evidence/2026-10-08.md)的结论只适用于它记录的样本和观察日期。
- 随包 [Skill](../skills/affinity-mcp/SKILL.md) 和 [SDK reference](../skills/affinity-mcp/references/sdk-verified.md#version-boundaries)把历史记录与 3.3 样本分开；没有新证据的旧案例，需要在目标构建上复验。仓库内容更新了，不代表已安装副本或实时 preamble 已经刷新。
