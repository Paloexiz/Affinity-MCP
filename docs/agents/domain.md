# 领域文档约定

本仓库采用单上下文：提供 Affinity MCP 代理、随包技能及其验证资料，不建立多上下文目录。

探索相关实现前，先阅读 [文档入口](../README.md)、[架构说明](../architecture.md)、[SDK 版本记录](../sdk/README.md) 和 [Agent hooks 约定](../hooks.md)。根目录 `CONTEXT.md` 与 `docs/adr/` 若存在，再读取相关内容；不存在时继续工作，不为补目录预填推测内容。实际作出新的架构决策时，按 [文档维护](../maintaining.md) 记录。

问题和分析区分以下边界：

- MCP 代理负责连接、请求、超时与结果转发。
- Affinity SDK/应用负责对象操作与实际文档状态。
- 随包 `skills/affinity-mcp/` 规定已验证流程及能力边界；已安装的技能副本需单独比较，不能默认与仓库版本一致。
- Agent 策略负责选择文档、调用范围、取证与验收；用户对视觉效果的要求需落实为代表样本与明确检查。

复用已有术语。建议与现有 ADR 冲突时，指出具体冲突及理由。静态实现绑定源码或提交；SDK 功能与历史版本记录标注观察日期、版本和证据来源；不要把个人会话或用户工作内容写入 docs。

架构/版本文档随仓库保存在 `docs/` 中，不代表随包 Skill 或已安装插件同步更新。记录新能力前使用 [SDK 验证方法](../sdk/verification.md)；版本与指引差异在内部 tracker 中关联，不把个人分析材料或其他被忽略的内容作为 docs 引用。修改代码或配置后按 hooks 约定同步相关技术文档，修改文档本身时避免触发自循环。
