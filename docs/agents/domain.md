# 领域文档约定

本仓库只有一个领域上下文，提供 Affinity MCP 代理、随包技能及验证资料，不设多上下文目录。

探索相关实现前，先读[文档入口](../README.md)、[架构说明](../architecture.md)、[SDK 版本记录](../sdk/README.md)和 [Agent hooks 约定](../hooks.md)。根目录的 `CONTEXT.md` 和 `docs/adr/` 如果存在，再读相关内容；不存在就继续工作，不要为补目录预填推测内容。确实要新增架构决策时，按[文档维护](../maintaining.md)记录。

分析问题时，先分清各自职责：

- MCP 代理负责连接、请求、超时和结果转发。
- Affinity SDK 与应用负责对象操作和实际文档状态。
- 随包 `skills/affinity-mcp/` 规定已验证流程及能力边界；已安装的技能副本要与仓库版本单独比较，不能默认一致。
- Agent 策略负责选择文档、调用范围、取证和验收；用户对视觉效果的要求要落成代表样本和明确检查。

沿用已有的术语。建议与现有 ADR 冲突时，指出具体冲突及理由。静态实现绑定源码或提交；SDK 功能和历史版本记录要写明观察日期、版本与证据来源；个人会话和用户工作内容不要写进 docs。

架构和版本文档随仓库放在 `docs/`，不代表随包 Skill 或已安装插件会同步更新。记录新能力前，先用[SDK 验证方法](../sdk/verification.md)；版本或指引上的差异在内部 tracker 里关联，不把个人分析材料或其他被忽略的内容作为 docs 引用。改过代码或配置后，按 hooks 约定同步相关技术文档；只改文档本身时，避免触发自循环。
