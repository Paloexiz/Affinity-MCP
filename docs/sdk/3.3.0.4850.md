观察日期：2026-10-08。本页汇总这一天的实验和 SDK 只读证据；每条结论只适用于注明的构建、样本和检查范围。

## 身份、对象和证据

应用原始版本字符串为 `Affinity 3.3.0.4850 Win32 (Sep 11 2026)`，其中 `shortVersion=3.3.0.4850`、`buildVersion=0`、`platformName=Win32`。来源为[脱敏证据摘要](evidence/2026-10-08.md) A-01。没有取得独立的 SDK 版本；也没有证据能把括号里的日期解释成官方发布日期。

| 能力 | 此构建可确认内容 | 状态与边界 |
| --- | --- | --- |
| 两种文字节点 | A-04：ArtText 入口接受 position，FrameText 接受 frameBox；A-06～A-08 各创建了一个对象 | 指定创建样本通过；不证明对象转换会保留排文/格式 |
| 水平段落 Align | A-07：`StoryDelta.createAlignX` 与 `DocumentCommand.createFormatText` 作用于实际文本子选区，Left/Centre/Right 读回与排文通过 | 单个未链接框样本通过；其他模式和链接范围未验证 |
| 水平枚举 | A-04：查到 9 个成员 | 不能把 hints 给出的较短列表当成全集 |
| 框与文字边界 | A-08：普通 visible box 为 400×220，exact visible box 约 151.30×61.07；框中心与内容中心明显不同 | 无效果等复杂条件下的简单样本通过；不构成通用测量/fit 配方 |
| 多行居中与文字块定位 | A-09：先设段落 Centre，再按字形边界中心水平平移；段落模式与内容中心读回、长短行渲染均通过 | 两个未链接 Frame 样本通过；文字、字号 runs、缩放矩阵、框尺寸和上下位置保持；链接框或复杂效果没有覆盖 |
| 框内垂直 Align | A-04：在查过的 wrapper、相关原生原型和命令入口里都没有找到对应的读写入口 | 已查入口缺口；官方 UI 有这个功能，不代表此 SDK 已经暴露，也不证明全部内部接口都不存在 |
| 调整框并保持字号、自动 refit | A-04：只有待测建议，没有当前构建的操作前后状态证据 | 未验证；缺前后字号、text scale、框几何、排文和溢出证据 |
| 链接/取消链接文本框 | A-04：`commands.js` 中能看到 `DocumentCommand.createLinkTextFrame` 和 `createUnlinkTextFrame` 入口 | wrapper 和成员枚举只读确认；写入、文本流范围或撤销都没有验证 |

来源：[脱敏证据摘要](evidence/2026-10-08.md) A-04、A-06～A-09 和公共 SDK reference。原生方法可能挂在原型链上，不能因为自身属性枚举为空就直接断言 API 不存在。

产品概念和 SDK 能力要分开：调整框让文字重排、缩放文字、把框收到内容大小，是三种不同动作；水平 Align 属于段落，垂直 Align 属于框。为了让某次画面看起来居中而移动整个框，不算设置原生垂直 Alignment。Initial Advance 指框顶到首条基线的距离，不能用水平的 FirstLineIndent 代替。官方[框排文帮助](https://www.affinity.studio/help/text-fitting-frame-text)和 [Text Frame 面板帮助](https://www.affinity.studio/help/panels-text-frame-panel)在这里只用于解释产品概念，不能证明 SDK 写入接口存在。

<a id="guidance"></a>
## 资料使用与能力边界

- 此构建的同步 close 只在注明的隔离样本上通过；异步路径、业务文档、保存提示和其他平台都未验证。关闭前核对授权和目标身份。
- A-02 所查 `Node.setText` wrapper 使用 `TextSelection.create(this.storyRange)`；普通替换样本通过，不构成保留混排格式的配方。
- 桌面路径使用 `app.userDesktopPath`，spread 前提按[具体命令](../../skills/affinity-mcp/references/scripting-pitfalls.md#documents-and-spreads)核对。实时提示不是保存或分享 hint 的授权。
- hints 可能把 SDK 的垂直 Align 缺口推成“文字永远顶端排文”，还会混淆 Initial Advance 和 FirstLineIndent；这些说法不能进入已验证的操作说明。

操作前核对[版本边界](../../skills/affinity-mcp/references/sdk-verified.md#version-boundaries)；文字工具按[文本流程](../../skills/affinity-mcp/references/sdk-verified.md#text-tool-choice-and-refit)选择，无法验证 fit 时停止该操作。[对齐流程](../../skills/affinity-mcp/references/sdk-verified.md#text-alignment-workflow)分别检查段落模式、排文和文字块位置，用几何读回与渲染核对结果。这些流程只适用于已注明的样本条件，不能补足表中未验证的 SDK 能力。

保存/导出、原生 Layout margin/bleed、跨 spread 写入、复杂选区、笔刷、滤镜、宏、文件异步和 AI 等能力，没有在这组 3.3 样本里逐项验证。旧版案例只能当待复验线索，不能自动继承为此构建的通过项。
