# Affinity 3.3.0.4850 Win32 能力记录

观察日期：2026-10-08（Asia/Taipei）。本页汇总该日期的实验与 SDK 只读证据；每项结论仅适用于注明的构建、样本和检查范围。

## 身份、对象和证据

应用原始版本字符串：`Affinity 3.3.0.4850 Win32 (Sep 11 2026)`；`shortVersion=3.3.0.4850`、`buildVersion=0`、`platformName=Win32`。来源为 [脱敏证据摘要](evidence/2026-10-08.md) A-01。没有独立 SDK 版本；没有证据将括号日期解释为官方发布日期。

主样本是无业务内容的隔离、未保存文档，640 × 480 document pixels、96 DPI、1 页，包含普通文本、20px/12px 混排和窄小溢出框。样本结束后关闭；插件仓库为 `0.1.10`，原始实验没有完整记录运行时安装插件/宿主版本。[脱敏证据摘要](evidence/2026-10-08.md) A-01～A-03。

## 框尺寸与 Align

| 能力 | 此构建可确认内容 | 状态与边界 |
| --- | --- | --- |
| 两种文字节点 | A-04：ArtText入口接受position、FrameText接受frameBox；A-06～A-08完成各一个对象的创建 | 指定创建样本通过；不证明对象转换会保留排文/格式 |
| 水平段落 Align | A-07：`StoryDelta.createAlignX`与`DocumentCommand.createFormatText`作用于实际文本子选区，Left/Centre/Right读回与排文通过 | 单个未链接框样本通过；其他模式及链接范围未验证 |
| 水平枚举 | A-04：已查到 9 个成员 | 不能把 hints 提供的较短列表当作全集 |
| 框与文字边界 | A-08：普通visible box为400×220，exact visible box约151.30×61.07；框中心与内容中心明显不同 | 无效果等复杂条件的简单样本通过；不构成通用测量/fit配方 |
| 多行居中与文字块定位 | A-09：先段落Centre，再按字形边界中心水平平移；段落模式及内容中心读回、长短行渲染通过 | 两个未链接Frame样本通过；文字、字号runs、缩放矩阵、框尺寸和上下位置保持；不覆盖链接或复杂效果 |
| 框内垂直 Align | A-04：在已查 wrapper、相关原生原型和命令入口中未找到对应读写入口 | 已查入口缺口；官方 UI 有该功能，不代表此 SDK 已暴露，也不证明全部内部接口不存在 |
| 调整框并保持字号、自动 refit | A-04：只有待测建议，没有当前构建的前后状态证据 | 未验证；缺前后字号、text scale、框几何、排文和溢出证据 |
| 链接/取消链接文本框 | A-04：`commands.js`中的`DocumentCommand.createLinkTextFrame`与`createUnlinkTextFrame`入口可见 | 包装器与成员枚举只读确认；没有写入、文本流范围或撤销验证 |

来源：[脱敏证据摘要](evidence/2026-10-08.md) A-04、A-06～A-08和公共SDK reference。原生方法可在原型链上；不能用自身属性枚举为空直接断言 API 不存在。

产品概念和 SDK 能力分开：调整框重排、缩放文字、将框收至内容是不同动作；水平 Align 属于段落，垂直 Align 属于框。移动整个框实现某次视觉居中不能算设置原生垂直 Alignment。Initial Advance 是框顶到首条基线的距离，不能用水平 FirstLineIndent 代替。这里引用的官方[框排文帮助](https://www.affinity.studio/help/text-fitting-frame-text)和[Text Frame 面板帮助](https://www.affinity.studio/help/panels-text-frame-panel)只证明产品概念，不证明 SDK 写入接口。

<a id="guidance"></a>
## 资料冲突与尚待同步内容

- 旧 Skill 把 Windows close 一概禁用；A-03 仅证明此构建同步 close 的隔离样本已可用。保留历史失败，不把新证据扩大到未测路径。
- 旧 reference 的 `TextSelection.from` wrapper 提醒有历史依据；A-02 显示当前 wrapper 已用 `create`。普通替换成功仍不等于保混排成功。
- 既有实时资料可能推荐旧 desktop getter、笼统要求所有 spread 编辑都切页或要求实验后立即写 hint。应对照当前公共接口、[按命令区分的既有 spread 记录](../../skills/affinity-mcp/references/scripting-pitfalls.md)和授权规则；实时提示不是持久写入许可。
- hints 可能将 SDK 垂直 Align 缺口推成产品始终顶端排文，并混淆 Initial Advance/FirstLineIndent；这些不能进入已验证操作说明。

随包Skill及[版本边界reference](../../skills/affinity-mcp/references/sdk-verified.md#version-boundaries)限定close、替换和资料冲突；[文本流程](../../skills/affinity-mcp/references/sdk-verified.md#text-tool-choice-and-refit)覆盖选型与未验证fit的停止条件，[对齐流程](../../skills/affinity-mcp/references/sdk-verified.md#text-alignment-workflow)纳入A-09。它们不补足表中的未验证SDK能力，也不证明已安装副本已刷新。

保存/导出、原生 Layout margin/bleed、跨 spread 写入、复杂选区、笔刷、滤镜、宏、文件异步和 AI 等未在这组 3.3 样本逐项验证。旧版案例只能作为待复验线索，不能自动继承为此构建通过项。
