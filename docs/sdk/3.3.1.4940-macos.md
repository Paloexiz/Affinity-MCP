# Affinity 3.3.1.4940 MacOS 批量、撤销与预览样本

观察日期：2026-10-19、2026-10-20。本页分别记录合成矩形的命令分组、查询、撤销及受限预览，以及可编辑文字/嵌入位图海报的原生 Margin/Bleed 与完整预览；不继承其他构建的完整能力目录。

## 身份与对象

应用自报 `Affinity 3.3.1.4940 MacOS (Oct  6 2026)`；独立 SDK 版本未取得。运行插件为 `0.4.3`，安装副本与对应仓库代理 hash 一致；宿主精确版本未记录。括号日期不解释为发布日期，也不使用后来的开发候选代填运行身份。[B-01](evidence/2026-10-19.md#b-01)

2026-10-19 样本为 800 × 600 document pixels、96 DPI、单 spread 的自建未保存文档。对象使用唯一合成标记，快照比较标记集合及六个变换矩阵分量；没有验证任意节点属性、混排文字、嵌套对象或生产工程。样本关闭后重新枚举确认移除。2026-10-20 的海报身份与范围单独记录于 [C-01](evidence/2026-10-20.md#c-01)，不把后来的样本补写为旧实验已经覆盖。

## 样本结果

| 用例 | 后置结果 | 状态与边界 |
| --- | --- | --- |
| 逐个插入或移动 3 个对象 | 3 次 undo 返回前态，3 次 redo 返回后态，再次 undo 返回前态 | 指定命令及对象样本通过；B-02 |
| 批量插入、共享选区移动、compound 移动 3 个对象 | 各 1 次 undo/redo/undo 匹配前后快照 | 指定样本通过；不是“一条脚本永远一次撤销”；B-02 |
| 移动 500 个目标，保留另 6 个标记 | 逐个命令需 500 次 undo；共享选区与 compound 各需 1 次；redo 和再次 undo 均匹配快照 | 六个非目标标记也在比较中；未覆盖历史裁剪、自动合并或其他属性；B-03 |
| 在同一工具入口分开/合并简单编辑步骤 | 减少工具调用后，目标矩阵、预览图像内容及恢复快照符合目标 | 是预设工作流对照，不是自主 Agent 指引前后验收；B-04 |
| 500 个矩形逐个/批量插入 | 合成标记与矩阵快照、渲染内容一致，撤销后匹配原始对象快照 | SDK 命令效率与整体耗时需分别判断；B-04 |
| 从稳定的 1000 项集合读取 500 项 | 重复 `.at()` 与一次转数组再索引得到相同结果序列 | 指定查询样本通过，不支持跨修改复用成员或属性快照；B-04 |
| 500 矩形插入，逐个/批量命令与全量/摘要回传组合 | 全量检查及完整预览相同；两种回传模式下批量路径的总体中位耗时均更高 | 小样本且有明显波动；指定后态样本通过，性能验收未通过，不能作为创建提速的依据；B-05 |
| 同向移动 500 目标，另保留 6 标记 | 五组配对的工具耗时合计有四组更快、一组较慢；另三组连续计时均较快且中位数下降；全部后态、图像和撤销恢复检查通过 | 只支持该预设工作负载的有限性能结论，不推广至插入或其他工程；B-06 |
| 每轮独立文档，500 矩形逐个/批量插入 | 同一宿主入口三组配对均为批量路径的创建到完整预览较短，中位耗时下降；全量标记、矩阵、逐轮图像和撤销恢复均核对 | 探索性三组；计时内保留导入与身份检查，不含夹具建立、清理或 Agent 决策；扩大样本未确认稳定收益，见 B-08；B-07 |
| 扩大至 12 组独立文档创建配对 | 24 个样本的全量状态、完整图像与撤销清理均匹配；批量九组较快、三组较慢，先后顺序分层方向不同 | 旧三组未并入；保留所有长等待，未确认稳定创建提速，不以总体中位数代替分层和区间判断；B-08 |
| 同一 batch500，独立 render 与单脚本 PNG 回传对照 | 12 对、24 个独立文档的标记/六矩阵/选区、完整图像和一次撤销恢复均通过；两个顺序层均支持缩短创建到图像交付时间 | 同一 Codex/functions 宿主上下文，中位 4325.5 → 2585ms；仅支持受限预览路径，不证明其他连接上下文的可用性、批量插入本身或自主 Agent 决策更快；B-09 |

## 海报预览补测

2026-10-20 的单画板合成海报为 600 × 800 px、96 DPI，含四个可编辑文字块、一个实际嵌入位图和原生 Margin/Bleed。实际 Margin getter、启用状态与有效安全框读回通过；Bleed 四边值/启用状态由文档设置界面观察，SDK 另核对 620 × 824 的实际外缘几何，未取得活动文档 Bleed 属性 getter 路径。[C-01](evidence/2026-10-20.md#c-01)

| 用例 | 结果与边界 |
| --- | --- |
| 默认 spread/selection render 与 PNG/CurrentSpread | 漏掉外侧 Bleed；裁切区十二对中位 5080.5 → 2946.5 ms，12/12 较快，但不能作为完整出血预览通过；[C-02](evidence/2026-10-20.md#c-02) |
| 完整选区 PNG | 只有已核对的全内容选区及恰好覆盖 native Bleed 的背景，`createForSelection` 才在此样本覆盖 620 × 824；`createForSelectionArea` 不等价，跨范围 PNG 也不保证逐像素相同；[C-03](evidence/2026-10-20.md#c-03) |
| 同一完整选区 PNG，分开两调用/合成一调用 | 另一组十二对均通过全文/样式/位图/几何/选区、全部 510,880 像素及四边标记检查；中位 4714.5 → 2638 ms，降幅 44.04%，两顺序层均支持收益；从空白文档请求计至完整图像 handoff，非前端 paint 确认；[C-04](evidence/2026-10-20.md#c-04) |
| 独立标线检查图 | 从同样本完整 PNG 派生，显示完整 Bleed、Trim 与有效 Margin；保留原图字节，去标线渲染的图像区逐像素一致。这是本地后处理，不是新增 SDK 能力，未纳入上述性能计时；[C-05](evidence/2026-10-20.md#c-05) |
| 标题越界与透明出血缺口负例 | 实际标题越过 Margin 左边约12.61px，底部右半310 × 14px透明；实心底图两名读者漏报出血缺口，棋盘底图的两名新读者均发现两项问题，对照无这两项误报；六对带线总耗时中位3611.5ms，本地标线加渲染64.25ms，不作加线提速或普遍检出率宣称；[C-06](evidence/2026-10-20.md#c-06) |

两组独立统计；实际撤销均恢复配置不变的空画板及选区，随后关闭指定样本。它们不验证任意选区、剪裁层次、真实照片或印前色彩/尺寸，也不证明新 Skill 的自主决策耗时。

## 不应推广的结论

历史位置差值不能单独证明恢复；本样本中它与已核对的实际撤销步数一致，不解释其他历史状态的失败。相反变换也不是通用回滚方案。

本页不证明所有批处理的请求到预览耗时更短，也不证明已安装宿主采用了修改后的 Skill。未验证 Windows/Linux、复杂文本与滤镜、长期内存、任意撤销历史、业务文档关闭、保存及已注明样本之外的导出场景。海报仍需读取目标工程的原生设置；完整选区导出的样本不替代 Bleed 属性读取或印前验收。
