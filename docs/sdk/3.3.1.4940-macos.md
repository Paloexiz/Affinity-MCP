# Affinity 3.3.1.4940 MacOS SDK 能力样本

观察日期：2026-10-19～2026-10-22。本页记录批量/预览、Margin/Bleed、光学对齐、文本流/关闭、SDK 入口、基础对象、画笔，以及文件、导出与混排样本；不继承其他构建的完整能力目录。

## 身份与对象

应用自报 `Affinity 3.3.1.4940 MacOS (Oct  6 2026)`。此前的实验都没有取得独立 SDK 字段；2026-10-21 的入口补测读到了 `Environment.sdkVersionStr="0.1"`，这个值不回填更早的记录。2026-10-19 批量实验运行时加载的插件是 `0.4.3`，安装副本与对应仓库代理的 hash 一致；宿主的精确版本没有记录。这个身份不扩展到后续其他实验。括号里的日期不解释为发布日期，也不用后来的开发候选版本代填运行身份。[B-01](evidence/2026-10-19.md#b-01)、[F-01](evidence/2026-10-21-sdk-availability.md#f-01)

2026-10-19 的样本是 800 × 600 document pixels、96 DPI、单 spread 的自建未保存文档。对象都带唯一合成标记，快照比较标记集合和六个变换矩阵分量；任意节点属性、混排文字、嵌套对象和生产工程都没有验证。样本用完后关闭，重新枚举确认已移除。2026-10-20 海报的身份和范围另外记录在 [C-01](evidence/2026-10-20.md#c-01)；后来的样本不能补写成旧实验已经覆盖的内容。

## 样本结果

| --- | --- | --- |

| 在同一工具入口把简单编辑步骤分开或合并 | 减少工具调用后，目标矩阵、预览图像内容和恢复快照符合目标 | 这是预设工作流对照，不是对自主 Agent 指引的前后验收；B-04 |
| 500 个矩形逐个或批量插入 | 合成标记、矩阵快照和渲染内容一致，撤销后回到原始对象快照 | SDK 命令效率与整体耗时需要分开判断；B-04 |
| 从稳定的 1000 项集合读取 500 项 | 重复 `.at()` 与一次转数组再索引，得到相同的结果序列 | 指定查询样本通过；不支持跨修改复用成员或属性快照；B-04 |

| 同一 batch500，对比独立 render 与单脚本 PNG 回传 | 12 对、24 个独立文档的标记/六矩阵/选区、完整图像和一次撤销恢复均通过；两个顺序层都支持缩短从创建到图像交付的时间 | 同一 Codex/functions 宿主上下文，中位 4325.5 → 2585ms；只支持受限预览路径，不证明其他连接上下文可用、批量插入本身更快或自主 Agent 决策更快；B-09 |

## 海报预览补测

2026-10-20 的单画板合成海报为 600 × 800 px、96 DPI，含四个可编辑文字块、一个实际嵌入的位图和原生 Margin/Bleed。实际 Margin getter、启用状态和有效安全框读回通过；Bleed 四边值与启用状态是在文档设置界面看到的，SDK 另外核对了 620 × 824 的实际外缘几何，没有取得活动文档 Bleed 属性的 getter 路径。[C-01](evidence/2026-10-20.md#c-01)

| 用例 | 结果与边界 |
| --- | --- |
| 默认 spread/selection render 与 PNG/CurrentSpread | 漏掉外侧 Bleed；裁切区十二对中位 5080.5 → 2946.5 ms，12/12 较快，但不能算完整出血预览通过；[C-02](evidence/2026-10-20.md#c-02) |
| 完整选区 PNG | 只有已核对的全内容选区，加上恰好覆盖 native Bleed 的背景，`createForSelection` 才在这个样本里覆盖 620 × 824；`createForSelectionArea` 不等价，跨范围 PNG 也不保证逐像素相同；[C-03](evidence/2026-10-20.md#c-03) |
| 同一完整选区 PNG，分开两次调用与合成一次调用 | 另一组十二对都通过全文/样式/位图/几何/选区、全部 510,880 像素和四边标记检查；中位 4714.5 → 2638 ms，降幅 44.04%，两个顺序层都支持收益；计时从空白文档请求到完整图像 handoff，不是前端 paint 确认；[C-04](evidence/2026-10-20.md#c-04) |
| 独立标线检查图 | 从同样本的完整 PNG 派生，能看到完整 Bleed、Trim 和有效 Margin；原图字节保留，去掉标线后渲染的图像区逐像素一致。这是本地后处理，不是新增 SDK 能力，也没有计入上面的性能计时；[C-05](evidence/2026-10-20.md#c-05) |
| 标题越界与透明出血缺口负例 | 实际标题越过 Margin 左边约 12.61px，底部右半 310 × 14px 透明；实心底图的两名读者漏报出血缺口，换棋盘底图后两名新读者都发现两项问题，对照图没有这两项误报；六对带线总耗时中位 3611.5ms，本地标线加渲染 64.25ms，不能算加线提速或普遍检出率；[C-06](evidence/2026-10-20.md#c-06) |

两组样本分开统计；实际撤销都恢复了配置不变的空画板和选区，随后关闭指定样本。它们不验证任意选区、剪裁层次、真实照片或印前色彩/尺寸，也不证明新 Skill 的自主决策耗时。

## 文本框链接、取消链接与异步关闭补测

2026-10-21 用了两个独立的 640 × 480px、96 DPI、单 spread、未保存合成文档，每个含两个框架文本。这次运行加载的插件为 `0.5.3`，应用 `buildVersion=1`；宿主精确版本和独立 SDK 版本没有取得。身份、原文、runs 和比较范围见 [E-01](evidence/2026-10-21-text-flow-and-close.md#e-01)，不沿用其他实验的身份。

| 操作/目标 | 后置结果与边界 |
| --- | --- |
| 链接到空目标框 | 57 字符的源 Story 接排到第二框，目标 `textBegin=39`；24/16/20px 字号、字体和段落格式保持，框几何、变换和文字缩放不变；[E-02](evidence/2026-10-21-text-flow-and-close.md#e-02) |
| 链接到已有格式的目标框 | 源全文、段落分隔和 11 字符目标原文合并为 69 字符，目标原文保持 18px 半粗体和居中；[E-03](evidence/2026-10-21-text-flow-and-close.md#e-03) |
| 对目标框取消链接 | 两组目标框都变空，全部 57/69 字符和已比较格式留在源框 Story，源框溢出；不会按可见文字拆分，也不会恢复链接前各自的原文；E-02、E-03 |
| 链接/取消链接的撤销重做 | 各自单步 undo/redo 和再次 undo 都匹配留存快照；两组恢复后的链接 PNG 与各自基线字节相同；只证明这些命令和这段历史；[E-04](evidence/2026-10-21-text-flow-and-close.md#e-04) |
| `closeAsync(callback)` / `document.promises.close()` | 各直接关闭一个 `isDirty=true`、`needsSaving=true` 的样本，没有保存，也没有出现提示交互，未保存内容被丢弃；回调没有错误、Promise 正常完成，重新枚举确认目标消失；不证明失败路径或关闭后恢复；[E-05](evidence/2026-10-21-text-flow-and-close.md#e-05) |

以上指定用例样本通过。取消链接后文字去了哪里、关闭会丢什么，必须在操作前说清楚；一般的关闭请求不等于授权丢弃用户工作。随包[链接文本流指引](../../skills/affinity-mcp/references/sdk-verified.md#linked-text-flow)和[异步关闭指引](../../skills/affinity-mcp/references/scripting-pitfalls.md#async-close)不依赖开发证据。这次没有测三框/跨 spread 链、从源框或中间框取消链接、写入新格式或保存重开；后续的限定结果和链首清空反例见[扩展补测](#layout-export-save)。两次都没有扩展光学对齐的链接流结论。

## SDK 入口、基础对象与文件补测

2026-10-21 按官方符号索引、应用内 wrappers 和 native 原型链核对了全量入口；行为补测分别使用脱离文档的值对象和明确授权的自建样本。调用入口的插件为 0.5.3，应用 buildVersion=1，SDK 自报 0.1；宿主精确版本没有记录。[F-01～F-07](evidence/2026-10-21-sdk-availability.md)

| 操作/目标 | 后置结果与边界 |
| --- | --- |
| 全量入口 | 455 个 API 对象/20 个模块，4,332 个文档原生方法中有 4,260 个有直接函数入口、72 个缺失；继承路径另计，有入口不等于功能通过；[F-01](evidence/2026-10-21-sdk-availability.md#f-01) |
| 基础对象、布尔、字符 | 值/克隆类型及 RGBA8 指定像素通过；四种矩形布尔的几何/像素/保护节点与恢复通过；普通字符 AB→A!B 保持已比较的格式/框/scale；[F-02～F-04](evidence/2026-10-21-sdk-availability.md#f-02) |
| 尺寸与笔刷 | 单参数尺寸对象读回通过，两个双参数工厂有语义反例；默认 PathBrush/RasterBrush 工厂返回 wrapper 占位错误，旧 VectorBrush 模块加载失败；[F-05](evidence/2026-10-21-sdk-availability.md#f-05) |
| 文件、导出与保存 | UTF-8 写读、同步复制、五种同步导出、异步 PNG/CurrentSpread 及 saveAs/重开通过；异步复制仍返回 NO_ENVIRONMENT；样本是指定预设的无出血矩形，不升级到其他区域/格式/保存模式；[F-06](evidence/2026-10-21-sdk-availability.md#f-06) |

本组 58 例中有 52 例达到限定目标、6 例未达到；成功的调用路径关联到 115 个文档方法，不是对每个方法都做了完整语义认证。另有 4,142 个有入口方法没有完成功能验收，72 个入口缺口、两个原生尺寸反例和一个异步复制失败分别保留。证据页保存的是脱敏后的后置摘要，没有附原始截图/文件。随包配方见[能力边界](../../skills/affinity-mcp/references/sdk-verified.md)和[文件验收](../../skills/affinity-mcp/references/sdk-verified.md#verified-file-and-export-workflow)。

## 已有路径画笔的获取与复用补测

2026-10-22 的 640 × 420px 双曲线样本通过：界面先为源线准备好真实纹理画笔，SDK 再从 `lineStyleInterface.lineStyle.pathBrush` 读取实例，独立克隆，把宽度从 120 改成 60，复用到目标线。源线已比较的字段、两条中心线和变换都保持，实际渲染及两轮撤销重做也匹配。[G-01～G-04](evidence/2026-10-22-brush.md)

有效写入分别使用 Weight、Brush、Type 单字段掩码和显式 options；这个样本里 All 掩码调用没有实际效果。两个默认画笔工厂仍抛占位错误，Texture 的 `LineStyle.create` 控制用例返回 INVALID_ARGS；没有找到 RasterBrush 的有效获取入口，也没有证明 SDK 能从零创建或枚举预设。界面准备和 SDK 复用分开记账，随包[已有画笔工作流](../../skills/affinity-mcp/references/sdk-verified.md#existing-path-brush-workflow)保留这些前提。

| 默认区域的完整 Bleed | PNG/CurrentSpread 和“用于打印”PDF 仍是裁切尺寸；Selection 包含所选背景的外缘。原生设置和完整印前目标没有验收；H-08 |
| IncludeImages 包离开原图路径 | 文件能打开，文字/几何保持，但图片渲染失真，导出的原图像素不符；恢复源路径后页面像素恢复。这个离线保真目标失败，原因和界面解包未确定；H-09 |

随包[扩展配方](../../skills/affinity-mcp/references/sdk-verified.md#extended-file-and-layout-workflow)按每条路线的前提使用；F 组的历史方法计数不随这次补测补填。样本和桌面输出都已清理，没有改动既有文稿。任意复杂排版、光学规则持久化、资源包可靠离线交付和其他未测项仍然保留；H-10。

## 不应推广的结论

历史位置差值不能单独证明恢复；在这个样本里，它和已核对的实际撤销步数一致，但解释不了其他历史状态下的失败。相反变换也不是通用的回滚方案。

其他平台没有独立复验记录；任意复杂文本/滤镜、长期内存、任意撤销历史、业务文档关闭以及指定样本之外的保存/导出都没有验收。海报仍然需要读取目标工程的原生设置；无出血导出和完整选区导出的样本，都不能替代 Bleed 属性读取或印前验收。
