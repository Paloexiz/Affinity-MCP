# 3.3.1.4940 MacOS 合成对象证据摘要

观察日期：2026-10-19。仅保留可复用的样本条件和后置结论；运行时标识、原始回包、个人路径及本机计时流水不属于本页内容。结果范围见[构建记录](../3.3.1.4940-macos.md)。

<a id="b-01"></a>
## B-01：身份与样本隔离

- 应用自报 `Affinity 3.3.1.4940 MacOS (Oct  6 2026)`，运行插件 `0.4.3`；安装副本与对应仓库代理 hash 一致。独立 SDK 及宿主精确版本未记录。
- 文档为自建、未保存、800 × 600 document pixels、96 DPI、单 spread；创建后读回实际尺寸。后续写入先检查已确认的文档身份，只关闭各自样本。

<a id="b-02"></a>
## B-02：三对象命令边界

基线包含六个带唯一合成标记的矩形。使用公共 wrapper，分别执行逐个移动、共享选区移动、compound 移动、逐个插入和批量插入三个矩形。逐个命令需三次 undo，其余各需一次；相同次数的 redo 返回后态，再次 undo 返回前态。

每个阶段按标记排序比较完整标记集合与六个变换矩阵分量。没有以 `isDirty`、历史位置或撤销动作次数单独判断恢复，也没有采用相反变换作为验收依据。

<a id="b-03"></a>
## B-03：500 目标与非目标状态

基线为六个保护标记及另 500 个目标矩形。显式关闭 transform 的合并选项后，逐个移动需要 500 次 undo 返回完整前态；共享选区和 compound 命令各需要一次。redo、再次 undo 仍匹配前后快照，保护标记包含在全部比较中。

这些结果只覆盖注明的命令、选项与历史状态，不证明任意命令不会合并，也不解释其他历史上的撤销不一致。快照没有穷尽颜色、效果、父级、选择状态等属性。

<a id="b-04"></a>
## B-04：预设流程与查询一致性

三轮交错对照使用同一工具入口、相同形状定义与目标。简单移动的分开读取/编辑/读回流程与合并流程均核对目标矩阵、预览内容及撤销恢复；500 矩形的逐个/批量插入在标记和矩阵快照、渲染内容上相同，撤销后回到前态。稳定 1000 项集合上的 500 次 `.at()` 查询与一次转数组再索引得到相同序列。

另在应用保持运行时使用新的代理连接区分资料准备与连续操作，不能称为冷启动应用或真实 Agent 的全流程对照。操作内计时、宿主调用耗时和渲染是不同边界；仅减少 SDK 命令不保证端到端更快。全部样本结束后关闭并重新枚举，确认样本文档不再存在。

<a id="b-05"></a>
## B-05：插入命令与结果回传的独立变量

同一工具入口的三轮 2×2 样本采用逐个/批量插入与全量/摘要回传两个变量。每个组合均在 10 个保护标记之外插入 500 个矩形，读取全部 510 个对象的标记与六个矩阵分量并与预期一一比较，使用相同的完整 spread 渲染；摘要模式只减少回传，不减少脚本内检查。实际 undo 恢复保护标记前态。

命令、定义、读回和序列化分别计时，工具返回和渲染另计。两种回传模式下，批量插入的总体中位耗时均更高，样本有明显波动；减少 SDK 命令或回包大小未通过创建到预览的性能验收。这不解释延迟根因，也不证明所有批量插入都会更慢，不能据此省略检查或预览。没有将后态样本通过写成性能验收通过。

<a id="b-06"></a>
## B-06：共享选区移动的端到端边界

基线为六个保护标记及 500 个目标矩形。五组配对交替先后顺序，分别在一个脚本内逐个移动目标，或对共享选区执行同一位移；两边均保留文档身份守卫、全部标记与六矩阵分量的预期值比较和完整 spread 渲染。两种路径的图像内容一致，逐个路径 500 次 undo、选区路径一次 undo 均恢复前态。

这五组记录的是编辑调用与完整渲染调用的耗时之和，不包含两调用之间的宿主编排时间；共享选区在四组较快、一组较慢，中位数下降。另三组相同任务使用从编辑调用前到完整渲染返回后的连续计时，包含中间解析和校验；三组共享选区均较快，连续耗时中位数下降，状态、图像及 undo 检查仍通过。

结论仅限该预设移动任务和本页构建；计时不含首次资料准备、夹具建立、撤销清理或真实 Agent 读取新旧 Skill 的决策耗时，未覆盖任意嵌套目标或业务工程，也不能移用于 B-05 的插入任务。执行时比较完整图像与恢复值，原始归档保留参考图像和逐轮检查结果，未逐轮保存全部图像及 undo 回包。三个用例的自建未保存样本均关闭并重新枚举确认移除。

<a id="b-07"></a>
## B-07：独立文档上的创建到预览对照

每轮使用独立自建文档及 10 个保护标记，在夹具建立和前态确认后开始任务计时；写入脚本仍在计时内导入模块并检查 `Document.current.sessionUuid`。逐个或批量插入 500 个矩形后，全量回传并比较 510 个标记及六个矩阵分量，再取得同范围的完整 spread 图像并比较内容。计时到图像比较完成为止，实际 500 次或一次 undo、关闭自身文档和重新枚举在其后分别记录；没有把清理时间算作创建提速。

同一宿主工具入口预设三组配对，顺序为逐个/批量、批量/逐个、逐个/批量。三组批量路径的创建到预览耗时均较短，中位耗时下降；状态、逐轮完整图像和撤销回包均保留，全部恢复保护标记并清理文档。另一个使用相同完整 Plugin 的诊断驱动器也完成三组独立文档对照，但两种入口的绝对耗时不能混作同一组结果。

分段诊断在部分慢调用中定位到 `DocumentApi.getCurrent()` 等待；额外只读检查没有消除所有后续等待，改用枚举后精确 UUID 绑定也未改善同任务中位耗时，因此都没有作为提速配方采用。独立文档结果不改写 B-05 的旧观察，也不证明该 getter 的应用内部等待机制，或任意清理后应用已经空闲。收益仅适用于本页简单对象、既定验证范围和三组配对；不包括首次准备、创建文档夹具、清理或 Agent 决策，不构成批量插入默认更快的结论。

<a id="b-08"></a>
## B-08：扩大创建样本的稳定性边界

另预先固定 12 组配对，分两块、平衡逐个先做与批量先做的顺序，共使用 24 个独立自建文档。B-07 的三组仅作探索记录，不并入本组。任务范围及验证保持一致：计时内保留模块导入、当前文档身份守卫、500 对象创建、全量回传和 510 个标记/矩阵检查，直到完整图像比较完成；夹具准备及实际撤销/关闭另记。24 张图像均与外部参考逐字节一致，实际 500 次或一次 undo 均恢复 10 个保护标记，全部样本文档关闭并重新枚举确认移除。

12 组中批量路径九组较快、三组较慢；逐个先做时三快三慢，批量先做时六组较快。总体中位数仍偏向批量，但顺序分层的方向不同，按两个中位数之比计算的区间也未排除反向收益。配对差与该比值是不同指标，不能互相替代；完整保留长等待，没有通过剔除离群样本或加入旧三组强化结果。

逐个与批量的总耗时中位数分别为 4972.5ms、4607ms，原口径降幅 `1−median(B)/median(S)` 为 7.35%，95% bootstrap 区间为 −9.95% 至 18.35%。配对差 `Δ=S−B` 的均值为 976.75ms、中位数为 467ms；两者区间分别为 [83.67, 2087]ms、[223, 852]ms。配对改善 `median(1−B/S)` 为 8.68%，区间为 [3.86%, 16.68%]。区间使用固定种子 20000、20000 次整对重采样，在块×顺序四格内各保留三对，以线性插值的百分位法取 95% 区间；双侧精确符号检验 p=0.146。每格仅三对且有顺序差异，正的配对区间不能单独作为稳定收益的确认依据。

<a id="b-09"></a>
## B-09：同次编辑回传完整 PNG 的受限预览路径

同一构建及安装插件 `0.4.3`，在一个独立子代理的同一 Codex/functions 工具上下文预设 12 对、24 个独立合成文档。两侧均为相同的 batch500 创建、800 × 600 document pixels、96 DPI、10 个保护标记及相同的完整名称/六矩阵和选区检查。基线随后独立调用 `render_spread`；候选在原 `execute_script` 内用公开同步 PNG/CurrentSpread 导出、`File.readAll(...).toString('base64')` 读回并删除本次唯一临时文件，确认检查字段及选区不变，再由宿主显式转发完整原生图像。已有 Desktop 文件权限不改变，拒绝覆盖预存输出；这不是把两次 Affinity 工具调用包装成一次。

计时从发出 create500 脚本前开始，到完整图像通过宿主 `image` 与 awaited `yield_control()` 实际交付后结束。包含导入、UUID 绑定、对象/选区检查、全部候选文件工作和预览回传；不含文档/夹具准备、诊断落盘、稍后的离线像素 oracle、undo/close 或模型决策。使用 `Date.now()` 墙钟，未测前端绘制确认；不能与 B-08 计至图像比较完成的端点混为同一指标。这里只验证规定流程，不验证自主 Agent 读取 Skill 后的整体效率。

两侧24个有效样本均核对510个名称及六矩阵、十个保护标记、最终500选区；12张基线JPEG完整解码为109087字节并与既有参考相同，12张候选PNG均800 × 600、480000个RGB像素与合成真值完全相同。JPEG与PNG编码不同，不作字节或元数据等价结论。每臂实际一次undo恢复十个基线标记及其选区，仅关闭自身样本并确认库存恢复；候选临时文件在返回前清除，结束后再次只读确认全部样本文件不存在。有效样本通过不代表所有准备尝试或任意节点属性均已验证。
