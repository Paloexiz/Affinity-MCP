# SDK 验证与记录方法

用途：当 Affinity 更新、现有记录与当前行为冲突，或者某个操作第一次被需要时，用这套方法留下可复核的能力记录。

## 先明确要证明什么

一次验证只设一个可判定的目标，例如“在这个构建的单个 FrameTextNode 上完整替换普通文本”，或者“框宽高不变时设置原生垂直 Align”。不要把“文字功能正常”当作验收目标，它没法判定。

动手前先查[能力索引](README.md)、对应构建页和[脱敏证据摘要](evidence/2026-10-08.md)。只在缺口处补证据。方法名没有出现在资料里，不等于发现了新问题；先确认已有记录里有没有同一件事。源码声明、构造命令、执行完成、状态读回和视觉结果要分项记录。个人会话和原始 issue 只留在本地 tracker。

## SDK 资料的适用范围

资料必须对应 Affinity 桌面应用和目标构建。Canva Apps SDK 面向浏览器应用开发，不能替代 Affinity 桌面 SDK 参考；搜不到匹配资料，也不能据此断言官方没有发布。

一条 API 事实要同时有应用内 `preamble`/SDK topics、匹配构建的 wrapper 声明和运行结果支撑。官方 Affinity 帮助能解释产品概念，但证明不了同名 SDK 入口可用；V2 帮助也证明不了 3.3 的菜单或 API 没有变化。相关边界见[几何参考](../../skills/affinity-mcp/references/page-geometry.md)和[脱敏 SDK 证据](evidence/2026-10-08.md)。原始输入输出只保存在本地归档里，docs 不引用它们。

平台字段只记录实验环境，不是操作配方的系统门槛。判断依据是当前 API、权限、参数、对象和后置结果；只有官方明确限制，或在相同前提下确认的差异，才算系统差异。见[通用配方与环境记录](README.md)。

## 每次记录的最小字段

| 字段 | 记录内容 |
| --- | --- |
| 用例 ID 与目标 | 用稳定 ID；写清楚操作、预期会变化的内容、不能变化的内容 |
| 日期与身份 | 观察日期按 UTC 日历日写为 `YYYY-MM-DD`，只写日期，不含具体时刻或个人本地时区；Affinity 完整版本和平台；SDK 独立版本没有取得就写“未取得” |
| 代理和宿主 | 插件清单版本、实际安装副本的版本或 hash、宿主版本；没有记录的项目要明确标出，docs 不写个人安装路径 |
| 证据层 | proxy / server / SDK / host / Agent 流程；问题出在哪一层，与目前推测的原因分开写 |
| 对象和范围 | 文档类型、运行时文档身份、spread、节点类型、单框/链接框、混排等；运行时标识不写进 docs |
| 前提 | 当前文档/当前 spread、权限、对象是否存在、是否已保存、允许的变更范围 |
| 动作 | 最小脚本/参数；只读、修改、持久化或可能付费要分别说明 |
| 后置结果 | 字符串、glyph/paragraph runs、框/页面几何、真实配置、文件内容或重读状态 |
| 视觉证据 | 需要视觉验收时，引用能进 Git 的脱敏图像；只有执行者当时看了一眼的，要明确说没有可重看的像素 |
| 结果 | 使用索引里的状态；失败写清阶段和原始错误；预期负例另外标注 |
| 清理 | 样本是否关闭、有没有留下文件、正式文档是否受影响、恢复是否确认 |
| 来源与局限 | 能进 Git 的脱敏证据摘要及证据键，或公开的一手来源；没有覆盖的平台、对象、选项和异常路径 |

取不到的字段写“未记录”，不要从当前仓库版本反推历史运行时版本。内部实验记录可以保存原始路径和运行时身份；整理进 docs 时必须去掉这些内容，并按[维护规则](../maintaining.md)检查引用目标没有被 Git 忽略。

连接预检使用随完整 Plugin 分发的[检查器](../../skills/affinity-mcp/scripts/affinity-mcp-smoke.mjs)。运行时显式选择安装根目录，再选 Codex 或共用启动配置；检查器会核对完整 Plugin 清单、代理入口和版本是否一致。只装了 Skill、没有插件清单时，不能拿它当安装副本验收。连接、preamble、宿主实际加载路径和 SDK 操作结果是四件事，分别核验，不能互相替代。[命令与边界](../../README.zh-cn.md#检查真实安装连接)。

## 执行顺序

1. **先只读识别环境。** 读取 preamble、列出 topic，再读这次要用的公共 wrapper。核对应用身份、文档清单、目标文档身份和保存状态；断线重连后要重新读一遍。按[随包发现要求](../../skills/affinity-mcp/SKILL.md)检查。
2. **查声明，缩小探针。** 优先用公共 wrapper；必要时读对应的 native imports、签名和参数范围。检查 native 对象可以看原型链，但反射只能证明“查过这个入口”，属性枚举为空不能当成功能不存在。[已发生的反例](3.3.0.4850.md#alignment)。
   全量盘点时，文档方法、直接入口和继承别名分开统计，不要把 inventory 的页面/类型数量当成 API 数量。按方法和构建保留成功、反例与未执行项，不能因为模块能加载就认定其中所有方法可用。[入口样本](evidence/2026-10-21-sdk-availability.md#f-01)说明了这套口径。
3. **按现有授权选择样本。** 需要写入时，只在明确允许丢弃的文档上验证。用户要求写文档或查资料，不等于允许关闭正式文档、保存文件、写 hint、发送 issue 或产生 AI 费用。已有具体授权可以复用，不要重复询问。
4. **固定目标，记录前态。** 脚本里再核对一次目标文档身份、spread 和节点内容/身份，先保存验收要用的原始值。定位不要只靠标题、数组顺序或全大写模式。运行时标识只留在本地证据里，不写进 docs。
5. **执行一次，检查真实后态。** 先对一个代表样本操作，分别检查目标内容、属性和效果。需要视觉验收就渲染，必要时检查导出文件。成功回包只是证据之一。
6. **超时先查状态。** 脚本可能已经执行过，不要自动重放；先查身份和已经发生的变更，再决定怎么继续。[代理生命周期](../architecture.md)。
7. **清理并归档。** 只清理本次样本和明确可删的输出。原始输入输出、运行时标识只保存在本地归档；正式 docs 只写脱敏摘要和证据键。不要为了清理去关闭无关文档。

下面这段只读示例用来读取应用身份字段，写法来自[脱敏证据摘要](evidence/2026-10-08.md)的记录模式。运行前仍要先满足 preamble 要求；示例代码本身不构成独立运行证据。

```js
const { app } = require('/application.js');
console.log(JSON.stringify({
  version: app.version,
  shortVersion: app.shortVersion,
  buildVersion: app.buildVersion,
  platformName: app.platformName,
}));
```

## 验收与操作目标对应

| 目标 | 必需证据 | 不够的证据 |
| --- | --- | --- |
| 完整替换文字 | 前后全文、长度、范围与目标节点身份 | 调用没有报错、可见首行正确 |
| 保留混排 | 字符及段落 runs、实际字号/字体、必要的文本流读回 | 全文相同，或字符数相同 |
| 链接/取消链接文本框 | 两框各自原文、合并后的全文和分隔符、格式偏移、flow 成员/顺序/范围、框几何与缩放，以及实际撤销/重做后的值及接排渲染 | 只构造命令、只比较共享 Story 全文，或把取消链接当作按可见文字拆分/恢复原始独立 Story |
| 调框并保持字号 | 框几何、文字占用、字号、text scale、溢出/末行与局部图 | 单个可见包围盒高度 |
| 原生垂直 Align | 固定框尺寸下的原生模式读回，改字后仍符合该模式 | 移动整个框，或把框裁小后看着居中 |
| 光学对齐模式与中文悬挂 | 分别记录模式读回、自定义规则来源、含标点/不含标点时的主体边界和局部图；固定文字锚点、框内段落对齐及对象边界定位分开比较 | 只有 Manual/Font 模式值、hints 没有命中、把 UI 规则编辑记作 SDK 写入，或用对象边界代替中文主体 |
| margin / bleed | 原生设置与几何分别读回；导出时检查实际范围 | 只有安全区几何或预览比例 |
| 标线检查预览 | 完整 Bleed 图像与同状态几何绑定，检查 Trim/Margin 坐标映射，保留无标记图并核对实际内容边界 | 在裁切区图上补白或画框、只有 SVG 生成成功，或把背景越过 Margin 判成错误 |
| 文件保存/导出 | 授权目标/范围、实际本地化预设、完成后的记录/真实文件及内容/尺寸、保存路径与两项状态；重开只在允许的样本上检查 | undefined、Promise 完成、只有文件头/大小，或只有 `isDirty=false`；同步和异步路径不能互相代验 |
| 同步关闭样本 | 明确目标文档身份，重新枚举确认消失，其他文档不受影响 | close 不抛异常 |
| 异步关闭与未保存内容 | 关闭前的保存标记与保存/丢弃授权、回调/Promise 的实际完成和错误、重新枚举目标消失及无关文档保持；写清是保存了还是发生过提示交互 | 入口存在、返回 undefined、请求已提交，或假定应用会弹保存提示/关闭后可以 undo |
| 代理不重放 | 模拟服务统计调用次数，并验证后续新请求能连通 | 单次普通脚本成功 |

依据：[3.3 文本/关闭样本](3.3.0.4850.md)、[几何验收参考](../../skills/affinity-mcp/references/page-geometry.md)、[代理回归测试](../../scripts/affinity-mcp-proxy.test.mjs)。这些是验收方法，不代表对应的 SDK 读写入口都已经可用；拿不到必需状态时，直接报告验证缺口。

光学对齐还要绑定字体、字号、标点字符集合、左右百分比和无标点基线。记录是否使用了自定义的 Manual 规则及其来源；没有自定义规则时，不能据此假定其他安装的默认规则相同。模式 API 存在，不等于规则表能读能写；同一对象的多阶段测量不算多个独立样本；Custom 之类的实验标签也不等于 SDK 枚举。参考[中文标点对照](evidence/2026-10-20-optical-alignment.md)。文字锚点生效时的悬挂结果，不能拿来推断“按含标点对象边界重新对齐也能消除偏移”。

标线检查图走单独的[检查流程](../../skills/affinity-mcp/references/inspection-preview.md)和[本地 SVG 工具](../../skills/affinity-mcp/scripts/inspection-preview.mjs)。生成检查图不读写工程；本地渲染、源图完整性和 Agent 的视觉判断分别验收，也不计入既有 SDK 单调用预览的耗时结果。透明像素要在棋盘底上才看得见，实心底可能盖住出血缺口；和无标记源图做内容保留比较要用 RGBA，不能要求检查图与原图合成后的 RGB 相同。读图验收要有未预告缺陷的负例和匹配对照，先冻结回答再对照实际几何，不能把少数读者成功推广成准确率。无依赖回归命令是 `node --test scripts/inspection-preview.test.mjs`，覆盖坐标原点、比例、未知/禁用 Margin、错配输入、透明源图保留和拒绝覆盖输出；这是本地工具测试，不是新的应用构建功能测试。

## 新增或更新构建页

- 新构建要有实际观察再建文件。先写身份和有限的样本，不要把上一构建的整页“通过”复制过来。同一构建以后新增案例，逐项补日期和来源。
- 只读看到入口记“只读确认”；写入后达到目标才记“样本通过”；只达到部分目标记“有限通过”，并写明缺什么。`NOT_IMPLEMENTED`、参数类型错误、权限拒绝、传输超时分别保留原样。
- 新观察和旧记录不一致时，两条都保留并互相链接，分别描述观察点；不要虚构首次引入或修复的版本。
- 同步更新[索引](README.md)以及相关 issue 的 Comments。能力账本建得再全，也不能代替针对随包 Skill、样本流程或代码的完整 issue 验收。
- 以后要发布操作规则时，另按实际授权修订随包 Skill 和版本信息，并验证安装副本。只更新本地 `docs/` 不会让已安装的插件生效。

## 可复制的单例记录

```markdown
### 用例 ID：操作和目标

- 观察日期（UTC，YYYY-MM-DD；只写日期，不含具体时刻或个人本地时区）：
- Affinity 构建/平台：
- SDK 独立版本：未取得 / 已确认值及来源
- 插件/实际安装副本/宿主：
- 对象、前提与授权范围：
- 目标与不应变化的内容：
- 动作和可公开的脱敏证据引用/键：
- 后置状态与视觉/文件证据：
- 结果状态、错误阶段及预期负例标记：
- 清理结果：
- 未覆盖范围与后续复验触发条件：
```
