# SDK 验证与记录方法

用途：当 Affinity 更新、现有结果与当前行为冲突，或任务首次需要某个操作时，留下可以复核的能力记录。

## 先明确要证明什么

一次验证只对应一个可判定目标，例如“在此构建的单个 FrameTextNode 上完整替换普通文本”，或“在保持框宽高不变时设置原生垂直 Align”。不要用“文字功能正常”作为验收目标。

先查[能力索引](README.md)、对应构建页和[脱敏证据摘要](evidence/2026-10-08.md)。只补缺失证据，不因为方法名没有出现就新建一个已有问题。源码声明、构造命令、执行完成、状态读回和视觉结果分别记录；个人会话和原始 issue 只在本地 tracker 内部维护。

## SDK 资料的适用范围

资料必须匹配 Affinity 桌面应用及目标构建。Canva Apps SDK 的浏览器应用开发资料不能代替 Affinity 桌面 SDK 参考；检索不到匹配资料也不能据此断言官方未发布。

API 事实需要应用内 `preamble`/SDK topics、匹配构建的 wrapper 声明和运行结果支持。官方 Affinity 帮助只能解释产品概念，不能证明同名 SDK 入口可用；V2 帮助也不能证明 3.3 的菜单或 API 没有变化。相关边界见[几何参考](../../skills/affinity-mcp/references/page-geometry.md)和[脱敏 SDK 证据](evidence/2026-10-08.md)。原始输入输出只在本地归档，不作为 docs 的引用来源。

## 每次记录的最小字段

| 字段 | 记录内容 |
| --- | --- |
| 用例 ID 与目标 | 稳定 ID；操作、预期变化、不能变化的内容 |
| 时间与身份 | 时间/时区、Affinity 完整版本和平台；SDK 独立版本若无则写“未取得” |
| 代理和宿主 | 插件清单版本、实际安装副本的版本或 hash、宿主版本；未记录项明确缺失，docs 不记录个人安装路径 |
| 证据层 | proxy / server / SDK / host / Agent 流程；区分问题发生层与当前推测原因 |
| 对象和范围 | 文档类型、运行时文档身份、spread、节点类型、单框/链接框、混排等；运行时标识不写入 docs |
| 前提 | 当前文档/当前 spread、权限、对象存在状态、是否保存、允许的变更范围 |
| 动作 | 最小脚本/参数；只读、修改、持久化或可能付费分别说明 |
| 后置结果 | 字符串、glyph/paragraph runs、框/页面几何、真实配置、文件或重读状态 |
| 视觉证据 | 需要视觉验收时引用可纳入 Git 的脱敏图像；只有执行者观察时明确没有可重看的像素 |
| 结果 | 使用索引的状态；失败写阶段和原始错误；预期负例另标 |
| 清理 | 样本是否关闭、是否留下文件、正式文档是否受影响、恢复是否确认 |
| 来源与局限 | 可纳入 Git 的脱敏证据摘要及证据键，或公开一手来源；没有覆盖的平台、对象、选项与异常路径 |

不能取得的字段写“未记录”，不要从当前仓库版本反推历史运行时版本。内部实验记录可保存原始路径和运行时身份；整理到 docs 时必须去除这些内容，并按[维护规则](../maintaining.md)检查引用目标不被 Git 忽略。

## 执行顺序

1. **先只读识别环境。** 读取 preamble、列 topic，并读取将要用到的公共 wrapper。核对应用身份、文档清单、目标文档身份和保存状态；重连后重新读取。遵循[随包发现要求](../../skills/affinity-mcp/SKILL.md)。
2. **检查声明，缩小探针。** 公共 wrapper 优先，必要时读取对应 native imports、签名和参数范围。native 对象检查可包括原型链，但反射只能证明已查入口；不能把属性枚举为空当作功能不存在。[已发生的反例](3.3.0.4850.md#alignment)。
3. **按现有授权选择样本。** 有写入需求时，在明确允许的可丢弃文档上验证；不要把用户要求写文档或查资料解释成允许关闭正式文档、保存文件、写 hint、发送 issue 或产生 AI 费用。已有具体授权可复用，不重复询问。
4. **固定目标，记录前态。** 脚本内再次核对目标文档身份、spread 和节点内容/身份；先保存验收所需的原始值。不要只凭标题、数组顺序或全大写模式定位。运行时标识只留在本地证据，不写入 docs。
5. **执行一次并检查真实后态。** 先对一个代表样本操作，分别检查目标内容、属性和效果；需要视觉验收时渲染，必要时检查导出文件。成功回包只是证据之一。
6. **遇到超时先查状态。** 脚本可能已执行，不自动重放；检查身份和已发生的变更，再决定如何继续。[代理生命周期](../architecture.md)。
7. **清理并归档。** 只清理本次样本及明确可删除的输出。原始输入输出和运行时标识只保存在本地归档；正式 docs 只记录脱敏摘要和证据键。不要为清理而关闭无关文档。

下面是用于应用身份字段的只读示例，提取自[脱敏证据摘要](evidence/2026-10-08.md)的模式。运行前仍需完成 preamble 要求；示例代码本身不构成独立运行证据。

```js
const { app } = require('/application.js');
console.log(JSON.stringify({
  version: app.version,
  shortVersion: app.shortVersion,
  buildVersion: app.buildVersion,
  platformName: app.platformName,
}));
```

## 验收与操作目标对应

| 目标 | 必需证据 | 不够的证据 |
| --- | --- | --- |
| 完整替换文字 | 前后全文、长度、范围与目标节点身份 | 调用无异常、可见首行正确 |
| 保留混排 | 字符及段落 runs、实际字号/字体、必要的文本流读回 | 全文相同或字符数相同 |
| 调框并保持字号 | 框几何、文字占用、字号、text scale、溢出/末行与局部图 | 单个可见包围盒高度 |
| 原生垂直 Align | 固定框尺寸下的原生模式读回，改字后仍符合模式 | 移动整个框或裁小框后看着居中 |
| margin / bleed | 原生设置与几何分别读回；导出时检查实际范围 | 只有安全区几何或预览比例 |
| 文件保存/导出 | 目标路径、真实文件存在与可读内容/尺寸，保存状态 | undefined 返回值或仅 `isDirty=false` |
| 同步关闭样本 | 明确目标文档身份，重新枚举确认消失，其他文档不受影响 | close 不抛异常 |
| 代理不重放 | 模拟服务统计调用次数，并验证后续新请求能连通 | 单次普通脚本成功 |

依据：[3.3 文本/关闭样本](3.3.0.4850.md)、[几何验收参考](../../skills/affinity-mcp/references/page-geometry.md)、[代理回归测试](../../scripts/affinity-mcp-proxy.test.mjs)。这些是验收方法，不意味着所有对应 SDK 读写入口已经可用；无法取得必需状态时明确报告验证缺口。

## 新增或更新构建页

- 新构建有实际观察后再建文件；先写身份和有限样本，不复制上一构建的整页“通过”。同一构建后续增加案例时，逐项追加日期和来源。
- 只读存在记录为“只读确认”；写入后达到目标才是“样本通过”；部分目标失败写“有限通过”并说明。`NOT_IMPLEMENTED`、参数类型错误、权限拒绝、传输超时分别保留。
- 若新观察与旧记录不同，保留原记录并交叉链接，描述两个观察点，不虚构首次引入/修复的版本。
- 同步更新[索引](README.md)及相关 issue 的 Comments。不要用能力账本建成代替 issue 对随包 Skill、样本流程或代码的完整验收。
- 将来要发布操作规则时，另行按实际授权修订随包 Skill 和版本信息，并验证安装副本；本地 `docs/` 更新本身不会让已安装插件生效。
